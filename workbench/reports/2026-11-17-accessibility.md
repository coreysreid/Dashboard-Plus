# Accessibility review of the example screens

Checked 17 November 2026 against [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and the [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). This is a review for Lane A, not a conformance claim. The 67 PNGs in `docs/screenshots/` are visual evidence; keyboard and accessibility-tree conclusions below come from the current templates and a running synthetic Smith household in headless Chromium. No physical screen reader was used.

## Findings, worst first

1. **Important — stock name suggestions do not announce the active match.** J2, `docs/screenshots/smith/12b-adding-stock.png` (also Garcia and Taylor). Type `kid` into Name, then Arrow Down. Three suggestions appear and the first gets `aria-selected=true`, but the combobox has neither `aria-controls` nor `aria-activedescendant`, and options have no IDs. The highlighted result is not connected to the focused input for assistive technology. Enter does pick it, so keyboard selection itself works. Expected: the focused input exposes the current option and its text. Suggested fix: give each listbox and option a stable ID; set `aria-controls` on the input and update or clear `aria-activedescendant` as the active option changes; keep `aria-expanded` in sync. Make “Keep ‘kid’ as you typed it” a selectable option too, or a separately focusable action. Verify with NVDA or VoiceOver. [WCAG 4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value); [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard).
2. **Important — form controls have faint boundaries.** J1/J2/J3, setup, settings and all add/edit screens, e.g. `docs/screenshots/smith/02-setup-answered.png`, `12b-adding-stock.png`, `21-settings.png`. The normal 1px control border is `#dcdcd4`: measured contrast against white card `1.38:1` and page background `1.27:1`. Dark theme border `#343a35` against card `#1f2420` is `1.35:1`. Expected: a visible boundary of at least `3:1` where that boundary identifies the input. Suggested fix: choose a darker light-theme and lighter dark-theme border, then measure both against the adjacent surfaces; preserve a separate obvious focus indicator. [WCAG 1.4.11 Non-text Contrast](https://www.w3.org/TR/WCAG22/#non-text-contrast). Text contrast spot checks passed: light muted text `5.65:1` against page, light links `5.82:1`, dark links `8.59:1`.
3. **Important — field errors and help are not programmatically tied to inputs.** J1/J2, setup, settings and all add/edit forms. Submit invalid values: a page-level `role=alert` says “Please check the highlighted fields. Nothing was saved yet.”; a visible field message follows the input, but the input has no `aria-invalid` or `aria-describedby`. The stock Name input also has no description for its help. Expected: the specific error/help is read when the user returns to its field. Suggested fix: give each message an ID, add it to that input's `aria-describedby`, mark invalid fields `aria-invalid=true`, and move focus to an error summary linking to the first invalid field. Exact summary wording: “Nothing was saved. Check these answers:” followed by linked field names. [WCAG 3.3.1 Error Identification](https://www.w3.org/TR/WCAG22/#error-identification), [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships).
4. **Important — the emergency sheet overflows a narrow view.** J4, `docs/screenshots/smith/09-emergency-sheet.png` and `10-emergency-sheet-medical.png` (Garcia and Taylor variants). At a 320 CSS-pixel viewport, the emergency sheet makes the document 385px wide, including the contacts table. Expected: reading at an equivalent 400% zoom on a 1280px desktop viewport should not need two-direction scrolling for text. Suggested fix: let long table cells wrap, or reflow each contact row to a labelled card on narrow screens; retain a printable table layout. Verify at 320px and 400% browser zoom. Settings overflowed by 8px in the same check, partly around the backup path. [WCAG 1.4.10 Reflow](https://www.w3.org/TR/WCAG22/#reflow).
5. **Minor — repeated link names hide record identity in a link list.** J2/J3, `docs/screenshots/smith/05-people.png`, `11-places.png`, `12-stock.png`, `16-pets.png` and equivalent screens. The synthetic Stock table had 27 links named exactly “Open”. Table context can supply meaning during table navigation, but a screen reader's links list does not distinguish them. Suggested fix: accessible name “Open Kidney beans” (using each row's primary name); keep visible “Open”. For private records, avoid inserting hidden sensitive values into the name. Likewise, make “Show” on concealed values identify the field, without revealing its value. [WCAG 2.4.4 Link Purpose (In Context)](https://www.w3.org/TR/WCAG22/#link-purpose-in-context).
6. **Minor — checkbox groups lack a semantic group name.** J1, `docs/screenshots/smith/02-setup-answered.png` and `21-settings.png` and the other households. “Things that can happen where you live (optional)” is a styled `span` above checkboxes, not a legend; the module selection group also has no legend. Each checkbox is labelled, but a screen reader entering the group may not hear its question. Suggested fix: use `fieldset` and `legend` for hazards and modules; keep the visible wording. [WCAG 1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships).

## Method and follow-up

- Ran the current application with a temporary Smith example, Chromium at 1280, 640 and 320 CSS-pixel viewports. Tested the Stock Name suggestion with typing, Arrow Down and Enter; checked generated roles and ARIA attributes; checked Stock list links and the Print button. The native Stock linked-list find box has the accessible name “Find item”.
- Measured color contrast from `src/dashboard/web/templates/base.html` tokens using the WCAG relative-luminance formula, checked both theme sets. The base type is 17px; do not infer that all text meets resize or reflow requirements solely from that size.
- The 320px viewport is a proxy for 400% zoom. Retest with actual zoom and a screen reader after the template fixes. Check focus visibility, focus order, escape behavior and status announcements in Firefox and Safari too; those were not verified here.
- Screenshots are generated by `python tools/make_screenshots.py`; fixes belong in Lane A's templates, then regenerate the examples. No changes to shipped code are made in this report.
