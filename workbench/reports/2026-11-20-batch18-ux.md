# 20 November build: three-household UX check

Checked **20 November 2026** against `origin/main` at `1b303b4`, decisions 0090–0094, and the invented Smith (AU), Garcia (US) and Taylor (UK) examples. Each of six runs used a fresh temporary data folder and system Chromium at **320px** or **1280px**. The test computer reported 21 November for the example-relative “today” fields; dates below quote the actual screen. No real household records or keys were used. The tests covered Mark done, Copies also kept, duplicate and `1/2/27` import, and Settings → Helpers. Findings are worst first.

## Findings

### 1. A household with no copy places cannot add one from its paper

**Taylor, both widths:** Open **Tenancy agreement**. Under **Copies also kept at**, the form says **“There is nothing to choose yet.”** There is no link in that form to **Places copies are kept** (`0` matching links). To use this field, the person must leave the paper, find the separate list, add a place, then return to the paper. The detour interrupts any unsaved edits on the paper; a return flow would need to preserve them. Smith and Garcia already have places, so their checkboxes work.

**Exact proposed empty-state replacement:** **“No places for copies yet. Add a place for copies, then return to this paper.”** Make **Add a place for copies** a link that returns to the current paper with unsaved form values preserved, or offer an inline add-and-return step. Core needs a return path and draft preservation; text alone cannot fix the detour.

**What passed in a 320px follow-up after the detour:** I added the invented **Blue USB drive** on Taylor's separate list, returned, ticked it and saved. It appeared on the paper, the **Document review dates** sheet and in `documents__documents.csv` in Export. The same sheet/export check passed with Smith's **Blue USB drive** and Garcia's **Shared family drive**.

### 2. Ambiguous dates look ready before confirmation

**All three households, both widths:** Import a two-row invented Stock CSV with an existing Water item and a new item dated `1/2/27`. The dry run says **“2 rows ready”**, lists the already-present Water item as skipped, and shows an active **“Send 1 row to Review”** button before **“These dates are read the way I meant”** is ticked. The new row is displayed under **Rows ready** with a definite use-by date. In a Smith 320px follow-up, clicking Send without ticking did **not** stage it: the page said **“Some dates could be read either way. Look at how each will be read, then tick the box to say they are right before sending.”** In that follow-up, ticking, checking again and sending staged only the new row on Review. Smith/Taylor read `1/2/27` as **1 February 2027**; Garcia reads it as **January 2, 2027**. The server guard works, but the ready count and active button promise a step the screen will refuse.

**Exact proposed line before confirmation:** **“1 row needs your date choice before it can be sent. 1 row already in your list is skipped. Nothing has been sent.”** Keep the localised interpreted date below it. Disable **Send 1 row to Review** until the date box is ticked; after the tick, show **“1 row ready to send; 1 matching-name row skipped.”** Core needs the send eligibility state in the dry-run view. Do not auto-accept the ambiguous date or existing name.

### 3. Documents Notes still prompt a second copy-location list

**All three households, both widths:** The **Copies also kept at** field is now a reusable picker, but Notes still says **“For example, ‘Another copy on Blue USB drive’ or ‘Family cloud folder’. This is a pointer to a copy, not the paper, a scan, a password or its number.”** A person following both hints can put a copy place in the picker and a different one in Notes. The sheet and export use the picker, so the two lists can disagree.

**Exact Notes help replacement:** **“Use Notes for anything else that helps you find or review this paper. Choose where copies are kept in ‘Copies also kept at’ above. Keep scans, numbers and passwords in a place you trust.”** This is a shipped `modules/documents/labels.toml` wording change for Lane A; Lane B did not edit the module.
