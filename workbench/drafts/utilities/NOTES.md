# Utilities promotion notes

Checked **2026-11-17** against shipped People, the Home layout draft and `docs/DESIGN.md` sections 5 and 6. Every provider, phone and account in `example.toml` is made up; this draft makes no claim about real outage numbers, fault response, billing or meter access. A household must use its own current provider information. No outside source or licence is used for the made-up examples.

**Contacts stay in People.** The provider and outage/fault line are two People contacts so the phone is edited once. People currently has no Utility provider or Fault line role; Lane A should add those roles before promotion so a household can find the contacts under Who to call and choose which appear on a printed reference. Do not put invented national fault numbers in a default pack. The current Utility sheet can show the contact's name but cannot declare `fault_contact.phone` as a sheet column. Until the core supports a linked field in sheets, its intro points back to People and it is not a complete offline fault reference.

**Meter locations stay in Home layout.** This PR adds `home_layout.meters`, its place link and an additive migration. The Utilities draft uses the meter's **name only** because the repository requires every draft to load beside today's shipped modules, and Home layout is not installed yet. This is a temporary handoff, not a reliable link: names can repeat or change. When Lane A promotes Home layout and Utilities together, change `utilities.services.meter` to a link to `home_layout.meters`, add the matching migration, and ask the household to resolve ambiguous names. The core must then show the full nested place path on the opened Utility service and Home sheet, and update it after a move. Existing Stock Places need the Home layout migration described in that draft's NOTES.md. A meter may be shared with a building; do not assume one exists or that the household may access it.

**Private accounts.** `account_number` and `notes` are sensitive, excluded from lists and sheets. Confirm that helper reads, search results, exports, backups and any future API obey that marking. The household should not store passwords, payment card details or login codes. There is no automatic bill import or meter reading in this draft.
