# Core work needed

This is a design only. The shipped core still uses the revision fingerprint in `src/dashboard/core/questions.py`; editing a field not listed in RULES.md currently returns a selected Yes to Review again. Do not simulate field-level behavior in the prompt file or household data.

The core needs **versioned, per-field change stamps** on records, including linked People, Stock items and the named parts of a nested place path. A candidate's review check should contain only the stamps for that question's listed fields plus permanent record IDs, not the private field values. The writer must advance a field stamp only when its normalized value actually changes. The water quantity check is a positive/zero state, not every numerical movement; the litre unit class is a semantic state. A review once raised should persist until answered, even if a later edit restores the old value. Tests need to cover one transaction changing a linked row and its selected row together.

**Upgrade:** First evaluate each existing answer against its stored revision check. Preserve an existing review reason if it is already due, changed, missing or no longer matching. Only for an unchanged, still-matching answer, seed the new field check from the current record without creating a fresh answer or resetting its date. Mark the check version so old and new forms cannot be mistaken. A changed answer has no trustworthy old field baseline; keep it in Review again until the person reconfirms. Use the same rule after restore and on a paired computer. Never store a plain or unsalted hash of a short private medication/dietary detail in a travelling answer: it could reveal the text by guessing. Per-field stamps are metadata, not content.

The person-facing review sentence stays generic for every module, including private People details. The question detail page can explain which *kind* of record changed (“A chosen kit changed”) without revealing private text. The established Yes/Not yet/Not relevant, Not now and date rules remain. The eight questions still use exact `match` conditions, and the remaining 41 have no record check.
