# Twenty questions worth asking, and forty to skip

Checked **2026-11-17**. Each example assumes at least **20 dated, usable points** and a change passing the Analysis guardrails in `docs/DESIGN.md` section 10.3; the shown basis is invented. A date near a change is a candidate, never an explanation. A question appears only if the household has saved the event or note and the measure explicitly allows that topic and subject. Cross-module pairings require a declaration. “Never ask” pairs fail the plausibility gate even if they happened on the same day. The person can answer **Yes / No / Not sure / That doesn't make sense**; only their Yes creates an explanatory annotation, still framed as their account.

The question wording is deliberately tentative. Some rows describe future measures or events that the shipped modules cannot yet capture; they are worked examples, not claims that these questions appear today. A change in a health measure should prompt record review and, where appropriate, a professional conversation, never an automatic diagnosis.
