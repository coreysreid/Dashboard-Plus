# Where a first-time assistant can still go wrong

Checked **21 November 2026** against one generated **9,951-character** starting message from the repository's invented Stock/Vehicles helper fixture (`tests/test_helper_starting_amounts.py`), plus decisions 0101–0103 and the shipped helper guide. This is a read-through and proposed checklist, not a test of Corey's private move. Ranked by potential harm; “covered” means the starting message says the rule, not that every assistant obeys it.

| Risk and actual guide coverage | What a careful move must do | Suggested guide addition or core gate |
|---|---|---|
| **1. Wrong or doubled Stock counts.** The guide explicitly distinguishes new item starting amount from later Stock in and warns against sending both. It does not stop a pair that would double a new item. | Separate new from existing items; verify a counted amount with the person; check the accepted batch/item total after each group. Do not call an old tracker count a purchase. | At Review, flag a new item with starting amount and a dependent bought movement for the same amount: **“This may count the starting stock twice. Check which amount is already on hand.”** |
| **2. Wrong existing record or place.** The guide says look up link IDs and use `{"ref": N}` for a missing record. It cannot establish whether two same-name items, people or “Shelf 3” paths are the same. | List existing rows and compare full Place paths, item units and context before using an ID. Ask the household about ambiguity. | A match preview should display full paths and existing item unit; never auto-merge by name. |
| **3. Private facts in ordinary text.** The guide names private field labels and says leave values for the person. Ordinary `notes`, `why` and receipt `source` can still contain revealing text if pasted from the old tracker. | Remove codes, account/payment identifiers and medical detail before sending a suggestion or source. Person enters allowed private fields in Dashboard directly. | Add to guide: **“Do not copy private facts into notes, names, why or receipt lines. Leave them out and tell the person.”** Keep the existing screened-text refusal. |
| **4. False completion.** The guide says every suggestion waits on Review and asks for unresolved items at finish. Accept all can leave a failed group waiting while others commit. | Track batch and row outcomes, not just send counts; verify accepted records and name waiting/refused rows. | Show accepted/waiting/rejected counts per move ledger; assistant finish words must say what remains. |
| **5. Unchecked water and dates.** Guide gives the drinking-water field and ISO date format. It cannot know whether a household's water is safe to drink now or whether a date from a foreign-format tracker means May or November. | Ask, leave blank where valid, and give the person ambiguous source dates on Review. | Exact guide sentence: **“Never infer Safe to drink or an ambiguous day/month order from a name; ask the household.”** |
| **6. Home layout is more than Places.** Guide lists Places and Connections and explains `inside`; it does not explain that nesting a shelf differs from a walkable connection, or that the helper should ask about doors. | Person checks rooms, nested spots and connections in Set up my home; helper should not invent an exit from a room name. | Add a short Set up my home paragraph and a link/route to it; mark unconfirmed connections as unknown. |
| **7. Receipt price mistaken for purchase history.** Guide correctly says `source.price` is Review-only. An assistant might still report spending or put price in Stock notes. | Check receipt source against the paper; save no price claim under current Stock schema; name unrecorded cost. | Keep Review-only wording beside each price and in the final assistant summary. |
| **8. Repeated or unmatched receipts.** The current guide covers `receipt_context` and the unmatched product line. It does not know if an old tracker and a receipt both describe the same goods. | Ask whether both are separate events; use the duplicate warning, Choose item or Skip line on Review. | Maintain origin mapping and review same-day basket before Accept all; never silently drop a line. |
| **9. Limits and stale guide copy.** Guide prints today's allowance, 500 waiting cap, 50/send and 120 requests/minute in the tested fixture. Its numbers age as work proceeds. | Refresh `dashboard_how_to_help` each phase, send 10–20 entries, and stop on refusal. Household controls Allow 200 more today. | Short dynamic preflight showing **left today / waiting now** before every large send. |
| **10. Incomplete grant or disabled module.** Guide lists only granted tables, but a needed link may live in a part the helper cannot see; the assistant may be tempted to create a plain-text substitute. | Ask the person to grant the relevant part or create the target themselves; do not invent a link or copy restricted values into notes. | Guide should say **“If the target list is not shown, stop and ask the household; do not replace a link with a name.”** |
| **11. Add-only helper API.** The guide says “suggest new records” but a move often needs correcting or merging existing rows. | Person makes edits in Dashboard; assistant can prepare a comparison, not submit an update as another new record. | Give an explicit **“I cannot edit an existing record with these tools”** reminder before a move. |
| **12. Transaction, retry and batching.** Guide covers all-or-nothing send, new request key and exact retry. A helper might regenerate a key after a timeout, stage a duplicate, or split a new link and its dependent entry across sends. | Keep key/body together until a result is known; keep `{"ref": N}` within one send; inspect returned batch ID. | Connector could expose a durable pending-send journal; until then, use the conversation ledger. |
| **13. Suggestions outside current lists.** Guide asks for a final list of things that did not fit. It cannot define bills, feeding, dose or other batch 20 work as shipped records. | Report each unsupported tracker section rather than squeezing it into Notes or a misleading module. | Keep the final “could not fit” list structured by source row and reason. |

The highest-impact follow-ups for Lane A are the double-count warning, private-text reminder, and a full-path match preview. The checklist is immediately usable without any core changes. It does not authorize a helper to read private values or raise its own limit.
