# Core work needed for CSV import

Checked 17 November 2026. The shipped Stock core has validated one-record writes and movements; it has no CSV upload, mapper, dry run, stocktake-correction operation or batch undo screen. The import service must parse locally, stage all rows, use module declarations for validation, then write only the reviewed plan in one transaction. Preserve source line numbers and record IDs for an audit trail, but avoid saving the raw file by default. Add a duplicate fingerprint scoped to the household, with a review override, and never treat foreign app IDs as local IDs.

Matching needs the shipped catalogue plus the household's own items first, nested Places by **full path**, and explicit conflict handling. Catalogue aliases are vocabulary, not permission to rewrite a person-edited Stock record. For an existing item, import changes to quantity, minimum, notes, category, place or drinking flag must each be visible in the dry run. Movement adjustments may handle “Add as Stock in”; “Set current amounts” requires a distinct audited stocktake correction so no fake purchase is recorded. Lot allocation, when available, must use actual dates and avoid replaying imported totals.

The dry run must use the same validation and quantity semantics as the final write, then revalidate against current record versions immediately before commit. A stale preview should stop and refresh, not silently overwrite intervening edits. Existing audit `source` supports `import:<source>`, but a full import batch, provenance and undo transaction still need core support. The template CSV is illustrative and is not an external interchange standard.

**Shipped follow-up, checked 20 November 2026:** Spreadsheet import now stages add-only rows on Review (decision 0080); the first two paragraphs above describe the original design, not what remains unbuilt. The [three-household run](../../reports/2026-11-20-restore-export-import-ux.md) found that the unchanged `EXAMPLE.csv` has no matching Places in Smith, Garcia or Taylor. Skipping the Place column lets three rows reach Review but drops their location; Garcia also skips the AU-formatted Use by column. A water row with no Safe to drink answer stays out, correctly. Core still needs a clear skipped-column summary, a same-name existing-item warning before Accept, and an import-only prompt for short dates such as `1/2/27` that may have come from another locale. Review cannot correct a single imported value; the person must edit the source file or omit a whole column. The older receipt-wide Undo and existing-record update ideas in this draft are not supplied by the shipped add-only importer.
