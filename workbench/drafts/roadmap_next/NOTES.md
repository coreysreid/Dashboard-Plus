# What Lane A must settle before scheduling this roadmap

Checked **28 November 2026**. [PLAN.md](PLAN.md) is a conditional order for the next twelve weeks, not a technical decision or release promise. Current main has only local sync stage 1, sharing choices without pairing, an unsigned Apple silicon preview and a portable Windows folder. Finance, a phone member, saved views, rule engine, comparison and Inbox are proposals. User 1's feedback and real-device tests decide the actual sequence.

The critical path to a phone is the independent remote-boundary review in decision 0089, then stage 2 identity/consent/choice-aware snapshot, then stage 3 durable member pushes to Review and outcome pulls. A phone cannot skip those steps. The critical path to a signed Mac release is a real downloaded-preview test, Developer ID access, signing/notarisation, visible Quit and backup/update recovery. The Windows installed path needs an MSIX prototype, a separate per-user data folder and portable-to-installed restore, while preserving USB use. These are different releases; a clean CI job alone does not prove either household install.

Finance starts as a local, person-confirmed ledger with a narrow reviewed CSV import. It must not derive a bank balance from Stock prices or Bills due dates, or persist forbidden headers from a real bank file. Categories come after transaction kind and exact balance rules; merchant rules only propose. My views can reuse accepted declarations only if source calculations, private Show and print remain equal. Comparisons need a genuine complete-week fact; household rules need exact dated evidence and one non-shaming card; photo Inbox needs a local image/OCR safety proof. None is a substitute for another's gate.

Before turning this into dated issues, Lane A should size the work with one engineer, reserve time for fixes after User 1's hands-on runs, and explicitly decide whether the second large track after installation is **sync/phone** or **Finance**. The plan offers Finance as the local fallback if remote security is delayed. Do not count parallel workbench drafts as available implementation capacity. Keep each technical choice in `docs/decisions/` and each release tied to its own acceptance evidence. No household data, signing credential or real bank export belongs in a planning PR.
