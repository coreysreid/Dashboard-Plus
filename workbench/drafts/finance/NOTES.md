# Core work needed for Finance

Checked **27 November 2026**. [PLAN.md](PLAN.md) is a proposed first module and later stages; the shipped Bills and Stock modules do not supply a transaction ledger. Do not infer a paid bill from `bills_insurance.commitments.next_due`, a bank transaction from `stock.movements.paid_total`, or a bank refund from `stock.refunds.amount`.

The first module needs declared account and transaction tables with stable IDs, revisions, history, Undo and exact money/currency handling; a dated starting-balance fact; an atomic two-leg same-currency transfer; account-balance and monthly-report readers that exclude transfers and missing/uncategorised coverage honestly; and private Show and choice-aware sharing for every list and detail. No full account/card number or login field may load under decision 0141. Set the Finance tables' default travel rule to local and require the household's 0140 choice before any history reaches a member. Helper access remains separate and closed by default. A remote member with only part of the ledger cannot present a complete household total.

CSV import needs a bounded, in-memory parser, a **before-preview** forbidden-detail screen for bank headers as well as rows, a column/date/sign/account mapping screen, row-level possible-repeat decisions, a durable dedupe journal scoped to account, atomic accepted rows and one Undo. It must not persist the original file, unsafe header, private filename, raw OFX credential or error excerpt. The current general spreadsheet Bring in/Review paths are not bank-file parsers or proof that this privacy boundary exists for Finance. OFX 1.x/2.x and QIF support belong to a later, separately tested parser with external-entity/network refusal and format/version limits; a file the parser does not understand is refused intact.

Splits need child allocations whose sum equals the parent and whose category totals never double-count the balance. Budgets need a month, category, currency, incomplete-coverage state and a documented refund rule. Bills links need one-to-one candidate matching without a duplicate payment or a second reminder; Stock purchase/refund reconciliation needs explicit person confirmation. Cross-currency transfers need typed sent and received amounts and a separate design. No finance chart should claim a complete month from partial imports, unpriced Stock ins or local-only member amounts.

Open household choices before promotion: account types and whether card debt is shown as an amount owed; starting-balance date; category tree from item 131; whether a refund offsets the original category or is shown separately; exact limits for bank CSV profiles, file size and row count; whether any finance sheet/export exists; and which data can be shared with each member. Test the invented [example CSV](example-bank-export.csv) and real-bank-like fixtures without saving genuine financial data. This draft does not add a bank connection, dependency, module or screen.
