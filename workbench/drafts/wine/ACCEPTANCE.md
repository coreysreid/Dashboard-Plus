# Wine collection: promotion acceptance checks

Prepared **20 November 2026** against the current draft and shipped core behavior for declarative modules (`docs/DESIGN.md` §§5–6). These are Lane A checks before Wine is switched on. Names, prices and dates below are invented examples, not buying, storage, drinking, health or valuation advice. Use a disposable household data folder and the draft module alongside shipped modules; never test on a person's records.

| # | Set up and action | Expected result |
|---|---|---|
| 1 | Load `workbench/drafts/wine/` beside the shipped modules and enable Wine collection in a fresh invented household. | Module and migration load with no problems; Wines, Bottles, Tasting notes and Wine collection sheet are reachable. No new dependency or remote host is required. |
| 2 | Open each empty list and its add form at desktop and 320px. | Plain empty state and correct labels. Wines asks for a name; Bottles requires a linked wine and a nonnegative count; Tasting notes requires linked wine, date and text. Focus, error summary and fields remain usable without horizontal scroll. |
| 3 | Add invented “Evening Red” with producer “Example Vineyard”, vintage 2023, region “Fictional Valley” and grape “Shiraz”; reopen and edit the region. | Record saves, shows entered words, and edit changes only that field. No region, variety or drinking advice is inferred. |
| 4 | Add two Bottle rows for Evening Red: 2 on “Pantry shelf” bought 20/11/26 and 3 on “Rack A” bought 19/11/26; set the first price to 12.00 in the household's currency. | Both entries remain distinct. The screen does not silently sum them into a stock figure or claim it scanned physical bottles. Price is optional and uses configured currency; 12.00 is the household's entry, not a market value. |
| 5 | Change the first count from 2 to 1 after opening one bottle; add a tasting note dated 20/11/26. | Count is 1 only because the person edited it. The tasting save does not also subtract a bottle. Undo/restore of either record does not invent a movement. |
| 6 | Leave Where kept empty on one Bottle row, then enter “Rack A”. | Needs attention asks exactly “Where are the bottles of Evening Red kept? Write a shelf or rack if it would help you find them.” It clears once the text is saved. Where kept is free text, not a `stock.places` link; moving a Stock place does not rewrite it. |
| 7 | Try count −1, blank count, a vintage below 1900 or above 2100, and a negative Price paid. | Each invalid entry is refused with a field error and no partial save. Zero bottles is allowed and shown as zero, never as missing or negative. |
| 8 | Set Bought on and Tasted on using 20/11/26 in an AU/UK/NZ household and 11/20/26 in a US household; try an impossible date and the opposite order. | Saved dates display in that household's format. Invalid or wrong-order dates get the shipped clear date error without being swapped silently. No due date or “ready to drink” reminder is invented. |
| 9 | Add a tasting with ordinary text and one with HTML-like text (`<b>sample</b>`). | Text is displayed as text, not run. The note appears in its list and general spreadsheet export; it is not marked private. The help text says this before entry. |
| 10 | Add a Bottle Price paid and inspect the Bottle list, exported spreadsheet, helper read with Wine granted, and Wine collection sheet. | Price is an ordinary field in the export and a granted helper's record read. The sheet omits price and tasting notes. Form help says price is exported; no screen promises it is secret. Helper without a Wine grant sees no Wine records. |
| 11 | Print Wine collection on A4 and Letter, light and dark, with two Bottle rows, a long place, and zero count. | Sheet prints the recorded wine, count, place and Bought on only, with a snapshot intro. Long text wraps and no content clips. It omits price, tasting notes and any implied market value. |
| 12 | Delete Evening Red while it still has Bottle and Tasting-note links, then delete those dependent rows deliberately and try again. | The first deletion is refused with a clear linked-record reason; linked history is not silently erased. After dependents are deliberately removed, delete/restore behaves as shipped core specifies and does not duplicate rows. |
| 13 | Switch Wine off, then on again. | Wine screens and reminders hide while off, but the invented rows remain and return unchanged when on. No other module's data or question changes. |
| 14 | Load each optional Wine example from `example.toml` for Smith, Garcia and Taylor in disposable folders. | Each has one Wine, one Bottle row and one Tasting note linked to that Wine. Dates resolve as example-relative dates; all names and notes are invented. The ordinary example households need not have Wine enabled. |
| 15 | Make a checked backup, edit a Wine count, restore that backup, then use Undo restore. | Count follows the chosen backup and returns with Undo; linked rows and sheet stay consistent. Do not rely on a printout or spreadsheet export as a backup. |

**Promotion gate:** checks 1–15 pass on the packaged build Lane A intends to release, including at least one mobile-width screen and both print sizes. The module migration remains confined to Wine tables under decision 0055. The draft's manual quantity, free-text place and ordinary price/notes are intentional v1 scope. If Lane A wants automatic bottle movements, a shared place picker or private prices/notes, that is a new product and schema decision before promotion, not an implicit promise of this draft.
