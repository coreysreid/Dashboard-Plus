# Core gaps before an Inbox can hold a suggestion

Checked **28 November 2026**. [PLAN.md](PLAN.md) is a design. Dashboard currently has no built-in Inbox, photo upload or local OCR. Important documents records **where** a paper is kept, never the file or number. The helper receipt path receives structured proposals, not an image. Decision 0141 guards text at record save, and 0143 broadens that guard, but neither proves a photograph can be read without persisting its bytes or that OCR will detect every identity or payment detail. The photo button must stay unavailable until a transient local pipeline and a fail-closed safety test exist; a paste/manual path can be first.

The core needs an allowlisted Inbox proposal type, bounded in-memory image decoder and local OCR (with a separately approved pinned dependency if needed), MIME/content and pixel checks, metadata discard, forbidden-content classification before any write, and a refusal that never echoes source data. Audit browser upload spooling, temporary files, crash reports and OS photo-library behavior on the actual platforms. An uncertain image must be discarded, not staged for a helper to inspect. Do not trust the filename, OCR instructions or an EXIF field. The normal 0141/0143 field guards remain the final check on each proposed value and on the whole helper send; they are not the only image gate.

Add a minimal local Inbox/Review state containing only safe target fields and bounded source fragments, with group/idempotency keys, 100-group/50-line candidate limits, 30-day reminder without silent deletion, explicit discard, accepted/rejected cleanup and a backup/export/sync policy. Accept must recheck target module, exact record ID, permission and current revision; a Stock receipt group needs dependency-safe atomic Accept/Undo, person-confirmed price and duplicate-basket review. A Documents proposal needs a safe name/kind/location contract and a person-chosen date meaning; never add an attachment. Bills reminders are a later allowlisted target, never payment evidence. Helpers require their own grant and cannot see local pending rows or decide them. Decision 0140 controls any accepted target record that later travels, but the Inbox queue and original photo stay local; the original photo is never stored in the first place.

Open design questions for Lane A: whether any local OCR engine can pass the no-persistent-image boundary on supported operating systems; whether an existing camera photo should be accepted with explicit outside-app-copy wording; the exact maximum bytes/pixels and safe text fragment length; how to identify a letter type without storing its body; a Review source-fragment retirement policy compatible with audit and restore; and whether a future photo/letter helper path needs a separate consent screen. No helper, scanner, OCR library, module or database table is added by this draft.
