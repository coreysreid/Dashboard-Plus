# Core work needed for money categories

Checked **27 November 2026**. [PLAN.md](PLAN.md) and the two CSVs are a draft, not a Finance module or a transaction classifier. `groups.csv` has 15 stable groups with one `flow` each; `categories.csv` has 120 stable leaves and AU/US/UK names. The core must load and validate keys, group links, regional words and aliases; let a household rename/add/archive categories without rewriting existing transactions; and preserve keys across catalogue updates and country changes. The group flow narrows a picker but never changes transaction kind or balance arithmetic.

The Finance module from item 130 needs a transaction kind distinct from category, exact minor-unit amounts, linked transfer legs, reviewed refunds and splits. A merchant rule needs a reviewed exact payee match, scope, precedence, versioned history and a **suggest only** result on Review. A helper proposal needs a separate grant and cannot save a category, rule or transaction. Free tags need stable IDs, safe text guards, bounded entry and explicit handling when renamed or removed. Finance records, custom names, tags and merchant patterns should start local; decision 0140's household choice governs any later sharing, while decision 0141 rejects fraud-grade values on every text path. None of these capabilities exists in the current core as a Finance picker.

The official ABS, BLS and ONS pages linked in PLAN.md were opened **27 November 2026** for broad coverage only. Their statistical category definitions, values and detailed tables were not copied into these original household rows. A future release should review current naming, legal reuse terms and real AU/US/UK household feedback before presenting these rows as a default. No user finances or real merchant/account data were used.
