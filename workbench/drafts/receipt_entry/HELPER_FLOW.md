# Receipt entry with an AI helper: household flow

Checked **19 November 2026** against the shipped connector (decision 0083), helper API (0067–0068, 0074), `modules/stock/tables.toml` and the live Review template. Every receipt line below is invented. This is the helper path for item 61; [FLOW.md](FLOW.md) keeps the later built-in receipt screen design.

## What the household does

1. In **Settings → Helpers**, make a **Look and suggest new records** key for **Household stock**. Connect an assistant desktop app using the settings block on that page. A Look-only key cannot send the receipt rows to Review. The household chooses whether an online assistant should see the receipt and ordinary Stock data before sharing the photo or text with it. A receipt may also contain payment or loyalty details, so cover or crop those first.
2. Give the **invented example receipt** to the assistant in its own app and say: **“Read only the goods I bought. Use my existing Stock items where the name and unit fit. Put clear Stock in rows on Dashboard Plus Review. Tell me which receipt lines you could not match. Do not guess a use-by date, place, drinking-water flag or item from a discount.”** The assistant does the reading; Dashboard Plus has no receipt-photo tool. A local assistant's own image support, and an online assistant's data handling, belong to that assistant.
3. The assistant uses `dashboard_tables` and `dashboard_list_records` to find granted Stock items and, if it needs a chosen place, granted Places. It sends only confident, valid `stock__movements` through `dashboard_suggest_new_records`: `reason=bought`, the existing item ID, amount in that item's unit, and the actual purchase date. It may include a real place or use-by date only if the household supplied it. It sends no price, card detail, tax, discount, refund or duplicate receipt line as a Stock movement. One receipt uses one stable `request_key`; a network retry repeats the same request and body. The helper API checks the whole call before staging and limits it to 50 rows; split a longer receipt into named groups with distinct keys.
4. Open **Review suggestions** in Dashboard Plus. Read every proposed **Stock in and out** row and its amount, linked item, reason and date. Press **Accept** or **Reject** on each. **Accept all** is only suitable after checking every row. The real Stock amount changes only when a person accepts. If Stock changed since staging, Accept may refuse and leave a reason; check the current batch and decide again. Keep a receipt beside you while reviewing, because the current Review page does not show original line numbers or an image.
5. For a **clear new good** that is absent from Stock, the assistant may first suggest a new **Stock item** with a name, category and compatible unit, but **no bought quantity**. The person accepts or rejects that item on Review. After acceptance, the assistant can read the accepted item ID from its suggestion batch and stage the bought movement as a **second** Review decision. If rejected, there is no movement. For an **uncertain line**, the assistant reports it in the conversation and stages nothing. For example: **“I put 2 clear Stock in rows on Review. I did not send ‘TOM SPECIAL 400G’ because I cannot tell which good it is. Tell me the right item or skip it.”** The household can answer in the assistant app and review a later suggestion. Never invent an item link or quantity just to finish a receipt.

## Invented two-line walk-through

| Receipt text the assistant reads | What can be sent now | What the household sees |
|---|---|---|
| `TOM TINNED 400G  4 @ $1.20` | If an existing Tinned tomatoes item uses tins: one bought movement of 4 tins, with the actual date. The `400G` is pack size, not four hundred tins. | **Pantry helper · 1 suggestion**; “Pantry helper suggests adding to Stock in and out: Item: Tinned tomatoes · Reason: Bought or added · Amount: 4 · Happened on: 19/11/26.” Buttons **Accept**, **Reject**. |
| `TOM SPECIAL 400G  1 @ $1.50` | Nothing, unless a specific existing item and compatible unit can be confirmed. | No fabricated Review row. The assistant names the unmatched line in its reply; the household tells it what good the line means or skips it. A later suggestion still waits on Review. |

If a different line plainly names a new good, the assistant can stage its new item first, then stage its bought movement **after** the person accepts the item. Today this means two Review visits. The assistant may poll its own batch for the accepted record ID; it cannot assume a future ID when it sends the first batch.

The exact labels in the first Review row are a **target for clear receipt Review wording**; the shipped generic Review renders field labels and values from the module, so the precise order and date display must be checked in the live UI. Its current heading and buttons are **Review suggestions**, “Pantry helper · 1 suggestion”, **Accept** and **Reject**. The helper's reason is labelled as its own words, not Dashboard's conclusion. For a future receipt-aware Review, use: **“Pantry helper read 2 goods from a receipt. 1 Stock in row is waiting. 1 line needs your choice. Nothing has been added yet.”** On an unknown row: **“We could not match ‘TOM SPECIAL 400G’ to your Stock. Choose an item or skip this line.”** Give **Choose item** and **Skip line** there. These future words must not be shown as though the current API supports an unknown row.

## Checks for this path

- A Look-only key cannot stage a receipt, and a helper without Stock access cannot list or suggest Stock. Private fields never appear in results.
- `2 FOR $7`, `TOTAL` and a `-$1.00` discount make no movement. `0.820 KG` stays 0.82 kg only if the linked item's unit is compatible; `12PK` is not automatically 12 packs.
- A repeat with the same `request_key` and body creates no duplicate. A different body with that key is refused. A clearly named new item needs two Review decisions; an ambiguous line is reported plainly and never converted into a made-up link.
- Reject leaves Stock unchanged. Accept creates one normal bought movement; if validity changed after staging, it stays pending with a reason. Turning off the key stops new suggestions, while existing Review rows remain for a person.
