# Home care Mark done: core needs

Checked **19 November 2026** against shipped `modules/home_care/`, `docs/DESIGN.md` §5.8, decisions 0063 and 0075, and the three invented example households. No household maintenance interval or legal requirement is asserted here. The [`FLOW.md`](FLOW.md) is the household screen design; [`ACCEPTANCE.md`](ACCEPTANCE.md) is the future build gate.

**What a household sees today:** Work done is a separate list. Adding a row does not update the linked job's Last done or Do again by; the person must open the job and edit those dates separately. The current generic one-step action can set fields only on its own row and must change a `show_when` field to hide itself. It cannot create Work done plus update the job, and a recurring job must keep Mark done available for its next completion.

**Core needed:** A form-backed, idempotent multi-record action that validates links and dates, checks a monotonic job revision, adds Work done, updates the job and writes an operation/audit record under one write transaction. The operation needs an opaque one-use ID, the Work done ID, before/after job dates and a revision so a retry or Undo cannot affect a later edit. Failed validation and stale submissions must leave both tables untouched. Undo must be a new audited transaction with a conflict check, not a deletion of history. This is new core capability; declaring `[[tables.jobs.actions]]` with the current contract would be misleading.

**Repeat data needed:** Optional, household-authored `repeat_count` and `repeat_unit` on a job (weeks, months or years), off by default, with a migration that leaves every existing job's repeat unset and preserves its current `next_due`. A repeat only **offers** one next date from the actual Done on date; a person selects, edits or skips it. Calendar clamping and local date order are specified in FLOW. Editing a repeat does not rewrite past Work done or an existing due date.

**Wording at promotion:** The shipped Home care help currently says “logging work done does not change it”; that stays true for the independent Add Work done form. When Mark done ships, the job page should say **“Mark done records the work and lets you choose the next date. Adding an older Work done entry changes no job dates.”** Keep the ordinary notes warning and the Home care sheet's omission of notes. A legacy Work done row must not be mistaken for a completed Mark done operation during migration.

**Way back:** The new fields are additive; old jobs and Work done rows keep their values. Turning off the new action leaves both lists usable as they are now. Removing the repeat option later should preserve entered due dates and history; removing an operation record must never replay or silently roll back a completion.
