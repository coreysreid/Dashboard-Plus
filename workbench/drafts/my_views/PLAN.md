# My own views, built from records already shown

Batch 24 item 133. Planned **27 November 2026** against decisions 0109, 0119, 0124, 0126, 0123, 0134, 0140 and the shipped declarations. This is a screen and data contract, not a built feature. A household chooses *which existing picture or list* it wants near the top of Home; it does not write a formula or decide how a source column is measured. Every picture has the same words and data table as its source page.

## What the household does

1. From Home, choose **Arrange my home page** then **Add a view**. The first question is **What would you like to see?** with source-owned choices such as **Rex's recorded weights**, **Food put out for Rex**, **Garden jobs done**, or **This month's feeding calendar**. The chooser lists only switched-on sources the household may open. A private source appears as **Private count view** until a session-checked **Show choices**; its chooser uses neutral subject numbers and does not identify who takes medicine.
2. Choose the subject if the source has one, then **How to show it?**. Offer only shapes the source declaration already supports. For Rex's weigh-ins, that is **Dots**, **Dots with a line between nearby readings**, or **Latest weight and change**. For feeding, it is **Bars by day, week or month** or the declared calendar. A line, measure, unit or calendar state cannot be supplied by typing it. Periods are the declared ranges or a checked date/month selection; a bar's unit is one of its recorded units, never a mixture. A fixed date range stays fixed; **Last 3 months** moves with the household's day and is labelled as such.
3. **Preview the view** shows its plain heading, subject, time span, units, coverage and caveat above the picture. **See the same values as a table** is available without the graphic, including each empty or incomplete period. A missing record reads **Nothing recorded in this period**, not zero or missed. Choose **Add another panel** for up to three separately labelled source panels; each keeps its own unit, scale and table. Then choose **Add to Home** or **Keep under My views** and **Save view**. Rearranging changes order only; it never changes records or an existing source chart.
4. Home shows the saved card with a short text answer for each panel and **Open view**. It has **Edit view** and **Remove from Home**; removing the card does not delete its configuration or any household record. **Print this view** opens a preview that includes each panel's date span, source, caveat and equal table. Print uses the same values as the screen; a private panel stays closed unless the household deliberately follows the private-print flow below.

Exact empty choice: **No views to add yet. Turn on a part of Dashboard Plus and record something, then come back.** A switched-off source on a saved view says **This part is switched off. Its records are kept; turn it on to see this view again.** A deleted subject says **The record this view used is no longer available. Choose another record or remove the view.** Never substitute a record with the same name.

## The bounded choices

| Source declaration | Safe household choice | Refused or unavailable choice |
|---|---|---|
| `chart.kind = "dots"` (0109) | The declared subject and x/y, allowed range and unit. Pet weights may also show the declared gap-broken line and recorded change words (0119). | A line where not declared, a fitted scale not declared, a health target, moving average, or a second pet on the same axis. Vehicle readings remain observations; no distance travelled is inferred. |
| `[[tables.*.bars]]` (0124) | The declared bar key, measure, allowed day/week/month, subject, optional single unit and source caveat. | A sum for a count declaration; adding pouches to grams; summing dose amounts; showing a money amount before Show; comparing a partial month with a full one as if equal. |
| `[tables.*.calendar]` (0119 and later) | One declared month, subject choice and fixed looks/legend; the same day list in words. A due date remains due, never done. | New colour meaning, a red missed day, an invented repeat or arbitrary state mapping. A blank day says only that no entry was recorded. |
| `[[tables.*.timeline]]` (0126 and later) | A **What happened** list panel for one declared subject, with the existing newest-first paging and day summaries. | A cross-subject feed, guessed cause, private detail before Show, or a future due date presented as an event that happened. |
| Number with change | A small **Latest recorded weight** card only where the dots declaration already has `change = true`, using its exact previous-reading words and unit. | A general arithmetic builder, percentage claim, speed or value inferred between readings, or a number from a source that has no change rule. |

Only accepted, undeleted records count, under the original source's local-day and correction rules. A saved view is a reference to a declared renderer, not a copy of its calculations. When a declaration disappears, changes version or fails its checker, the view stops with the neutral explanation above. Do not silently repurpose its key. The water composition page is useful, but it is a special calculation rather than a declared `chart`; adding it to this builder needs its own reviewed source contract. Item 132's two-measure comparison also needs its own evidence gate, not an unguarded choice here.

## What is saved, and what stays closed

Store a random view ID, schema version, one to three ordered panel configurations, title policy and whether it is on Home. Each panel holds only a source declaration identity (`module`, `table`, renderer kind and key), exact subject global ID when needed, an allowed period choice (relative or fixed), and allowed unit/filter choice. The first version uses source-generated titles and offers no free title, note or caption box: a view must not become a place to store a password, code, full card/account number or ID detail forbidden by decision 0141. Any later custom text needs the same refusal and no-echo guard on every save/import/helper path before it is considered. Do **not** store chart values, pre-rendered HTML, medicine or person words, a user-written expression, raw SQL, or an unchecked column name. Revalidate every saved choice against the live declaration and switched-on module at each rendering. Default saved layouts to this computer; decision 0140's information choices do not automatically authorise sharing a layout that identifies a private source. If layouts later sync, give them their own explicit consent and filtered contract.

A private source on Home, the builder's chooser, saved-view list, address, ordinary HTML and default print says **Private view · Show details** or an allowed count only. Its title, subject, legend, links and table must not reveal a name or value. If one panel is private, the saved view's closed title is neutral too; public panels may still show their own summaries. **Show details** is a session-checked POST on the private panel, never `?show=1`; the revealed response is `no-store`, focuses the revealed content and does not persist after reload, Back or a Home revisit. Source-generated titles still need the neutral closed form before Show; no custom title can smuggle a medicine name or fraud-grade detail into the card. A custom view creates no new export, helper, notification or sync payload; the underlying records keep their own decision 0140 sharing choices, including a household's deliberate private sharing. Rendering a card must not override a list or detail set **Only on this computer** when the view is opened on another member.

**Print** defaults to closed cards even after a screen Show. If a household asks to print shown private details, a separate preview must list exactly which cards and details will be on paper and require **Print these details**; no silent opening of a folded private table. Until the core has that checked flow, print counts or neutral placeholders only. The printed page names its period and source and retains the table and caveat; CSS cannot hide the only words that explain a symbol.

## Sketches in words

**Desktop, arranging:** a left column lists available views by part (Pets, Stock, Things to do), a centre panel asks subject, picture and period in that order, and a right preview shows the answer, graphic and equal table. Keyboard order follows left to right. Each option says why unavailable: **A line is offered only for charts with recorded readings and a gap rule.** Reordering Home cards uses **Move up** and **Move down** buttons as well as drag; the order is announced in words.

**Phone, 320 px:** one column. **My views → Add a view → Choose records → Choose picture → Choose period → Preview → Save**. The title, as-of words and caveat precede the compact graphic; **See as a table** follows it. The six or fewer on-screen choices wrap, with no sideways scrolling or chart-only controls. On Home, one card occupies a row and its source and period fit before the **Open view** button. A private card has one prominent **Show details** button, never a name-shaped teaser.

**Print:** a heading **My view · Rex's recorded weights · Last 3 months**, as-of date, then the chart with labels and its complete table, plus **Recorded values are observations; the line does not show values between readings** when a declared line is used. Page breaks keep chart, legend and first table rows together where possible; continuation pages repeat table headings. No Edit, Show, Move or Open links print. High-contrast and monochrome copies retain shapes, patterns, labels and the table.

## Build order and checks

1. Build a source registry from checked declarations only; stable declaration IDs and version/migration handling must be defined before saved views. List allowed shapes, measures, date ranges, units and filters from each declaration, not user input. Test a switched-off, removed and renamed declaration.
2. Add a local saved-view record and builder with one known public view (Rex's weight) first. Live-render through the source's chart/data-table path, with a single consistent records snapshot. Correct a reading, delete it, Undo and restore: source page and saved view must agree exactly. Test one reading, same-day readings, a gap, no readings, wrong unit, a household date boundary and a fixed versus moving range.
3. Add the declared bars and calendars without changing their meaning. A feeding in pouches stays separate from grams; one unknown amount is counted but not zero; a blank calendar day is not missed; a due Garden job never appears done. Test current-week **so far** words and the equal table at 320 px and desktop.
4. Add private sources only after a route-by-route leak audit: builder, saved list, Home, view, URL, search, print, export, helper API, sync change log, cache and browser Back. Test Show by POST with and without the session token, no-store, no-script fallback, reload and a private title. Confirm there is no free-text title or caption path for a full card/account number, code or ID detail; any future one must refuse such input without echo. A hidden module or subject never leaks through an error or fallback.
5. Add reorder and print with a keyboard and screen reader. Test VoiceOver/TalkBack where a phone app eventually ships, desktop screen readers now, large text, light/dark/high contrast, A4/Letter print and a page with many saved cards. The chart's summary, accessible table and links must name the same periods and values.
