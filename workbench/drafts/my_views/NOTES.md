# Core needs for My views

Checked **27 November 2026**. [PLAN.md](PLAN.md) designs a household-built Home view, not a shipped screen. The generic dots, bars, calendar and timeline declarations already calculate individual source pages. The core still needs a checked registry of those declared view identities and permitted options; a versioned saved-view table containing configuration only; builder, Home card, reorder and print UI; live rendering and equal tables from the source calculation; and neutral handling when a module, declaration or subject goes away. A number with change is available only where a source already declares change words. The water breakdown needs an explicit registry contract before it can be selected.

Private views need a new composite privacy boundary: a closed title, subject, chooser, Home card, URL, ordinary HTML, print and export must reveal no more than the underlying source before a session-checked POST Show. Existing per-source Show cannot simply be replaced by a saved `shown` flag. The first version has source-generated titles and no free text; a later title or caption input would need decision 0141's fraud-grade refusal without echo as well as the private-name guard. A separate private-print confirmation is needed before printing shown detail; default print stays closed. Decision 0140's household sharing choices filter records, while a saved view's layout may itself identify a private subject, so layout sync needs a separate decision and consent. Keep layouts local for the first build. There is no arbitrary formula, SQL, cross-list arithmetic, cause label, mixed-unit sum or automatic health/safety verdict in this proposal.

This draft has not run a browser or real-device test. Lane A should use the acceptance sequence in PLAN.md, then add cases for a corrected/deleted record, a module switch, a changed sharing choice, an empty period, private title and session Show, A4/Letter print, 320 px, keyboard and screen reader before promotion.
