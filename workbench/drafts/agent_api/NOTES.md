# Agent API draft notes

Checked **18 November 2026** against `docs/plans/agent-api-v1.md`, shipped module and web security guards and decisions 0055/0059. The API skeleton is in Lane A's draft PR awaiting Corey's decision 0067. [ABUSE_CASES.md](ABUSE_CASES.md) is a design and test catalogue for the planned v1 boundary, not an assertion that current `main` exposes `/api/v1/`.

The plan already covers bearer-only auth, local Host and Origin checks, module grants, private-field exclusion, staged suggestions, idempotency, bounded bodies and a daily proposal cap. The highest-priority behavior to verify in the build is **no live side effect before a person accepts** and **no hidden module name, ID or private value in any response or proposal validation**. A local program that has a key is authorized within its grant; Origin checks cannot stop local malware or a key willingly given to an online service.

**Core and product gaps raised by the catalogue:** no sustained read/request rate limit or pending-queue cap; no stated handling for bidi/control characters or instruction-like text displayed in Review; and the planned 403 for a known ungranted table versus 404 for an unknown table may disclose the table's existence. **Critical:** a link column can expose a hidden module through its raw ID, `to` schema target or guessed-ID validation even when formatted names are hidden. Apply grants to link fields throughout read, schema, proposals, Review and errors. Also decide how to screen credentials pasted into persistent `why` or values before they enter proposal backups. Add measured limits and plain errors if these gaps are confirmed. Keep the raw key out of logs and backups and describe third-party access honestly in Settings. Items 49–54 will specify the API contract, household jobs, later update/delete/grant design and live UX check separately.

Item 51 adds [later change-suggestion screens](CHANGE_SUGGESTIONS.md) and [acceptance checks](CHANGE_ACCEPTANCE.md). V1 is still add-only; these need monotonic revisions and person-only conflict/undo services before any endpoint is exposed.
