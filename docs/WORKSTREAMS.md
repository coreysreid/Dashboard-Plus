# Workstreams: two agents in parallel

Two AI agents build Dashboard Plus at the same time, each in its own lane, so
they never edit the same files. Corey reviews pull requests as usual. This page
is how the agents coordinate; read it before starting any work.

## Lanes

| Lane | Agent | Owns (may edit) | Delivers |
|---|---|---|---|
| **A: core and M1 modules** | the first agent | `src/`, `tools/`, `.github/workflows/`, `modules/`, `docs/DESIGN.md`, `docs/ROADMAP.md`, this file | M1: core features, the People and Household stock modules, release checks |
| **B: examples, guides, research and project files** | the second agent | `examples/`, `docs/MODULES.md`, `docs/research/`, `SECURITY.md`, `CONTRIBUTING.md`, `.github/ISSUE_TEMPLATE/`, `tests/test_example_*.py` | the module authoring guide with the vegetable garden as a worked example; public-project files; researched notes for the first country packs (M3) |

People and Household stock moved from Lane B to Lane A on 9 November 2026,
because the second agent had not started yet. Lane B now has work that does not
touch the program or the M1 modules.

Shared files that both lanes may touch, **adding rows only**: `README.md`,
`INDEX.md` files, `docs/decisions/INDEX.md`, `tests/INDEX.md`. `PROJECT_MAP.md`
is regenerated by whoever merges second (`python tools/make_project_map.py`).

## Rules

1. Each agent works on its own branch from `main` and opens its own pull
   request. Never push to the other lane's branch.
2. Before starting, pull the latest `main`. Before asking for a merge, merge
   `main` into your branch and re-run every check.
3. Decision record numbers: Lane A uses **0034 to 0059**, Lane B uses **0060 to
   0079**, so the two never pick the same number.
4. If you need a change in the other lane's files, do not make it: describe it
   in the "Requests" table below in your own pull request, and carry on with a
   stand-in in your tests if needed.
5. All the project rules in `AGENTS.md` apply: no personal data, synthetic test
   data only, a decision record for every technical choice, short `INDEX.md`
   files, plain language for Corey.
6. The contracts below are fixed for M1. Changing one needs a note in both
   lanes' pull requests.

## Contracts between the lanes

**Watch views** (Lane A builds, Lane B uses): the `watch` section in
`tables.toml`, exactly as in `docs/DESIGN.md` section 5.1.

**Printable sheets** (Lane A builds, Lane B uses): `sheets.toml`, exactly as in
`docs/DESIGN.md` section 5.2. Added since the first version: a column written as
`person.phone` prints a column of the linked record, so "Who to call" can show
phone numbers.

**People tables the wizard writes to** (Lane B builds, Lane A uses). Module name
`people`. These must exist with these names and types; Lane B may add more
columns and tables.

| Table | Column | Type |
|---|---|---|
| `people` | `name` | text, required |
| `people` | `lives_here` | boolean |
| `people` | `relationship` | choice |
| `people` | `phone` | text |
| `roles` | `person` | link to `people`, on_delete = "cascade" |
| `roles` | `role` | choice, including `emergency_contact`, `neighbour`, `doctor`, `vet` |
| `roles` | `priority` | integer |
| `important_info` | `person` | link to `people`, on_delete = "cascade" |
| `important_info` | `detail` | text, sensitive |

**Household stock** (Lane B builds): module name `stock`, with a `watch`
section that uses `running_low`, `expiring` and a water `supply`.
