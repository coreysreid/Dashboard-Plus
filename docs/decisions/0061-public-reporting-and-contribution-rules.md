# 0061. Public contribution and private security reporting routes

- **Status:** Accepted
- **Date:** 2026-11-09
- **Decided by:** Codex (working from Corey's Lane B brief)

## In plain words
Contributors should know how to help without exposing a household's private information.

## What we chose
Provide a security policy, a plain-language contribution guide and three focused issue templates. Direct possible privacy or security issues to GitHub's private vulnerability reporting when available; otherwise ask for a private channel without posting details.

## Why we chose it
- Public reports are easy to find, but security details can create risk before a fix exists.
- Focused templates help contributors explain an issue or idea with synthetic data.

## What else we considered
- One general issue form: it would miss useful details for module and country pack suggestions.

## What this costs us (the downsides)
- The fallback still needs a maintainer to arrange a private channel.
- Templates need to stay current as the project grows.

## How hard it is to undo
Easy. Change the documents and templates.

## We should revisit this if
- Reports repeatedly arrive without enough detail, or private reporting is unavailable to contributors.
